Start here

Oinam.DEV holds design and development assets, ideas, and standards for AI, and their agents, tools, and harnesses. The documentation is only beginning, and this page is where it begins.

If you are an agent

To design or build a page, read the components guide. It is plain text: the rules, and a page for each component.

To work in the repository, read AGENTS.md first. It is the canonical source for the scope, audience, standards, and style that every oinam.dev project inherits. A project may add rules of its own on top, but not loosen these.

Everything here is open and free. There are no accounts, and nothing sits behind a sign-in.

Components

The components are plain HTML, CSS, and JavaScript: custom elements for structure, native elements for the work, and no framework. Link them, or copy the files and make them yours.

Without classes

A page of plain HTML, with no classes and no custom elements, can wear the components' look with one stylesheet, classless.css, linked in place of ui.css: 

<link rel="stylesheet" href="/ui/classless.css" />

See it working: the classless demo is a whole page, with a header, writing, a table, a form, questions, and a footer, made with that one link and nothing else. View its source; there is not a class in it.

It brings the same tokens and the same Base as the components. The body becomes one column at a measure made for reading, and the writing in it is spaced as in <onm-prose>. A submit button looks like the solid button, and any other button like the outline one. Fields, labels, checkboxes, tables, details, and dialogs look as their components do. A variation, linked after it, changes it the same way it changes the components. An element with a class of its own is left alone.

It is for a page that has not yet earned the components: a readme turned into a page, a quick form, a note.

  • Take a copy. The installer brings it with the rest, into ui/classless.css. It imports tokens.css and base.css from beside it, so keep the three together.
  • Or link a release, to try it on a page. A release never changes, so the page keeps its look when a later version renames something. 
    <link rel="stylesheet" href="https://oinam.dev/ui/releases/0.11.0/classless.css" />
  • To grow into the components, link ui.css after it. The components win wherever the two speak. The other way round does not work: added after ui.css, it would dress bare buttons and fields over the components.

Why it is a sheet of its own, and Base is not classless, is in why.md.

Icons

Every icon in an Oinam product or asset is from Phosphor, an open set of 1,512 icons drawn by one hand, under the MIT license. They are served from /ui/icons/ in four weights: regular for screens, fill for a state that is on, and bold and duotone for assets.

Copy an icon into the page inline, so it takes the color of its text. Every icon's name and tags are in icons.json, to find one by what it means. How to use one, and what to do when one is missing, is in icons.md.

Standards

A change is not done until every point below holds.

  • Linted, with the ecosystem's standard linter and zero warnings.
  • Formatted, by a formatter configured in the repository.
  • Evaluated. Anything that drives or wraps a model ships with evals that measure whether it does its job.
  • Tested, with a suite that passes. A bug gets a failing test first.
  • Followed. The checks run on every push, and a red check blocks.
  • Documented, in one place that is kept current.

Writing style

  • Plain text. No emoji or emoticons.
  • American English, with the Oxford comma.

What comes next

Prompts, skills, harnesses, and their evals will be documented here as they land. To try other fonts, corners, and colors on the components, go and play.
