Oinam UI v0.4.0

Components in plain HTML, CSS, and JavaScript, made so that the first draft of a page does not look like every other page an AI has made. Custom elements give a page its structure, native elements do the work, and there is no framework and no build step in between.

Agents: this page is for people to look at. Everything on it is also in guide.md, as one page of plain text, and in registry.json, as data. The reasons behind the rules are in why.md, and what changed in each version is in the changelog.

Install

Take a copy. The system is meant to live inside your project, not to be linked from this site. One line puts every file in ./ui/, and from then on they are yours. 

curl -fsSL https://oinam.dev/ui/install.sh | sh

Link your copy

Three lines in the <head>, with the path as your site serves it. The stylesheet is the system; the two scripts are only for the theme toggle and the few elements that need behavior. 

<link rel="stylesheet" href="/ui/ui.css" />
<script src="/ui/theme-init.js"></script>
<script type="module" src="/ui/ui.js"></script>

Or hand it to an agent

One line is enough. The front page sends the agent to the guide, and the guide tells it to take a copy first, and then how to design with it. 

Read https://oinam.dev/ and build the page with it.

Without a shell

Every file under /ui/ stands alone and has no dependencies. registry.json names them all, and which ones each component needs. Download those into one folder, keeping their names.

Tokens

Two colors do all the work: ink, which is nearly black, and cloud, which is nearly white. Every other shade is ink mixed into cloud, so the dark theme is the same page with the two swapped. Every value in the system is named in tokens.css, and again in tokens.json, in the Design Tokens format, for tools that cannot read CSS.

These values are Base, the default design. A variation is a new look made by changing tokens and nothing else: a small stylesheet of your own, holding only the values that differ, linked after this one.

--color-ink
--color-ink-soft
--color-ink-faint
--color-line-strong
--color-line
--color-cloud
--color-milk

Wrap

<o-wrap> centers the page content and keeps it off the edges. It is 1600px wide at most; add narrow for a page of reading.

Stack

<o-stack> is a column. Children sit one under the other, a gap apart. The gap attribute takes a space step: 1, 2, 3, 4, 6, 8, 12, or 16.

Row

<o-row> is a row that wraps. justify takes between, center, or end, and align takes start or baseline.

Grid

<o-grid> lays out equal columns, as many as fit, with no breakpoints to write. min takes small or large to change how narrow a column may get.

Headings, paragraphs, links, and code are styled as they are. Two classes mark the special cases: .eyebrow above a heading, and .lede for the opening paragraph.

Ratio

<o-ratio> keeps a picture, a video, or a frame to a fixed shape, and crops it to fit. It is 16 by 9 unless ratio says 4/3, 1/1, or 21/9.

Scroll

<o-scroll> is a frame for something too long to show at once. It scrolls inside, with a thin bar, so the page keeps its length.

Button

A class, because <button> and <a> already do the job. data-variant takes outline or ghost, and data-size takes small, large, or icon. While it works, aria-busy shows a spinner and turns away further presses.

Button group

<o-button-group> joins buttons that belong together into one piece. It suits outline buttons best.

Field

<o-field> keeps a label, its control, and a line of help together. The control takes .input, whether it is an input, a select, or a textarea.

Used for sign-in only.

Input group

<o-input-group> puts something before or after a field, inside its frame: a <span> for a unit or a prefix, or a small button.

Choice and switch

A checkbox or a radio button sits inside a <label class="choice">. A switch is a checkbox that says so, with role="switch".

Slider

class="slider" on an <input type="range">, which already works with the keyboard and with touch.

Toggle

A toggle is a button that stays pressed. It is a checkbox underneath, so it needs no script and sends its value with a form: class="toggle" on the <label> around the <input>. <o-toggle-group> sets several side by side in one frame; with radio buttons of one name inside, only one can be pressed at a time.

Accordion

<o-accordion> goes around a set of <details>. The browser already opens and closes them; give them the same name and it keeps one open at a time.

Is it free?

Yes. Everything is open, under the MIT license.

Do I need a framework?

No. It is HTML, CSS, and JavaScript, and it works with or without one.

Is there a build step?

No. Link the files, or copy them.

Tabs

<o-tabs> turns a run of sections into tabs, each named after its heading. The arrow keys move between them. Without the script, the sections simply follow one another.

Dialog

A class on <dialog>, which already traps focus, closes on Escape, and dims the page. The buttons open and close it by naming it, so there is no script to write. With data-side it is a drawer that slides in from an edge.

Delete the file?

This cannot be undone.

Popover

class="popover" on any element with the popover attribute. The browser opens it from the button that names it with popovertarget, closes it on Escape or a click elsewhere, and keeps it above everything. There is no script to write.

Office hours

Eight to five, every day but Sunday.

Menu

<o-menu> is a button and the short list of actions it opens. The list is a popover of plain <button> and <a> elements, with <hr> between groups. The arrow keys move between items, and choosing one closes the list. Without the script, Tab still reaches every item.

Open

Tooltip

<o-tooltip> shows a few words about a control when the pointer is over it or the keyboard is on it. Inside go the control and a <span role="tooltip">, tied together with aria-describedby.

Frees the berth for the next boat

Copy

<o-copy> goes around a <pre> and adds a button that copies its text. 

mise run check

Theme

<o-theme> goes around a button and makes it a light and dark toggle. It remembers the choice, and follows the system until one is made.

Toast

<o-toast> is where brief messages appear, in a corner, and go away again. A button with data-toast shows its message when pressed, with no script of your own.

Example

<o-example> shows markup at work and prints its source beside it. Every specimen on this page is one, so the code you read is the code that is running.

Written once

Contribute

The system grows from what real projects turn out to need. When a page needs something that is not here, build it in the project by the same rules, then send it back as a design need. It does not have to come with a fix. CONTRIBUTING.md has the rest.
